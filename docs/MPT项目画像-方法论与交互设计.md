# MPT项目画像：方法论、对话更新与阶段演进设计

日期：2026-10-30。范围：项目画像产品设计；本次不修改应用业务逻辑或现有用户数据。Pencil MCP恢复后，已在正式设计文件新增P10.42—P10.47六页，并导出至designs/mpt-portrait/。这些是设计状态示意与交互目标标注，不是已开发的应用功能。

## 1. 资料范围与结论

已逐页读取“销售策略/MPT矩阵生成与销售策略展示.pptx”的4页，以及“MPT销售策略Agent整体训练规则与交互工作底稿(2)(1).xlsx”的00—15共16张工作表的非空单元格内容。第一张PPT是矩阵展示的主依据；其余3页和工作簿用于解释判断、追问与人工核验规则。本次采用文档内容提取，未在PowerPoint中打开渲染检查。

来源定位：

- PPT第1页：6×6 M/P矩阵、投入风险、T轨迹、当前位置与历史点。
- PPT第2页：原始信息→事实分层→当前有效值→矩阵映射→策略输出；人工闸门。
- PPT第3页：T0—T5、暂停、回退、重招及采购轮次。
- PPT第4页：模糊拜访的最少必要追问、P判断六槽位。
- 工作簿01—03：M阶段、P0核真、P1接触与首访。
- 工作簿04—08：P2/P3教练、早晚期P4/P5、采购与收入并行、转售与采购主体。
- 工作簿09—11：16条业务规则、标准交互输出、15个训练案例。
- 工作簿12—15：项目跟进字段、Agent权限、追问协议与36格策略。

核心结论：**项目画像是“项目落地成熟度M × 我方订单位置P”的当前状态、独立设备采购进程T、关键事实与演进计划的组合。** 它不是三项平均分，也不是M/P/T同步增长的流水线。M:P是坐标，不是比例或比值。

用户已确认的产品口径：

1. CRM实体与M/P/T独立：S0保留线索实体，S1起保留商机实体；已有商机可以处于P0。不因P变化自动转换实体或改CRM阶段。
2. M1×P4/P5的SED规则、E0—E3的完整等级定义继续保留待补，不自动补造规则。

资料命名差异：PPT第1页轴为P1“首访”、P2“决策链”；工作簿15矩阵为P1“摸链”、P2“拜访”。界面统一采用业务含义“P1 接触与首访”“P2 决策链支持”，详情保留原资料名称；不把名称差异当成额外阶段。

## 2. M：项目本身能否落地

### M0 规划

有开发意图或规划，土地、并网、许可尚不明确。核实项目主体/SPV、区域与规模、团队、开发路径和下一实际动作。不能用去年规划公告代表当前阶段。

下一目标：确认真实开发动作；土地控制、并网或许可等已启动时，形成M1建议，并由人申报/核验。

### M1 开发推进

土地控制、并网、规划等已有启动，核心障碍尚未关闭。分别记录每项“做了什么、取得什么、还缺什么、谁负责、下一节点”。申请已受理≠批准，咨询≠正式申请。

下一目标：按项目所在市场、技术类型及采购范围确认核心RTB适用清单，关闭重大开发障碍，形成M2建议。不能以完成事项数量达到比例自动升级。

### M2 核心RTB

重大开发障碍基本关闭，具备可建设基础，但不代表融资关闭或立即开工。核核心许可/并网文件、未关闭条件、自持或转售、未来业主、选型对经济性的影响。

下一目标：验证收入、成本、融资、采购及风险分配的可执行路径，进入M3投资级RTB推进。M3是围绕这些条件推进，不等于全部完成融资。

### M3 投资级RTB推进

围绕可融资收入、预算、合同、采购及风险分配推进。重点问融资具体卡点、设备Bankability、收入结构、EPC、预算、技术商务偏差和竞争。

下一目标：关闭影响NTP和开工准备的关键条件，形成M4建议；不凭融资意向认定融资完成。

### M4 开工准备

接近NTP与开工，核融资、合同生效、采购、交付窗口、付款担保和现场接口。核EPC定标权限、业主/投资方批准以及剩余采购范围。

下一目标：取得实际NTP/开工及履约准备证据，形成M5建议。临近开工不等于我方中标。

### M5 开工建设

已开工，关注我方合同、交付、变更、剩余采购、验收及回款。不再追已关闭主设备订单。增容、二期或补供需识别独立范围，必要时关联新线索/商机。

不新增M6；交付、验收、回款保留业务字段及CRM S6—S8，不强行塞入新的M阶段。

## 3. P：我方在谁的订单中处于什么位置

- **P0 线索位置**：尚无有效订单位置，先核真、找公开业务联系路径。不代表项目一定处于M0。
- **P1 接触与首访**：定向邮件、回复、NDA、预约与首访，重新核实当前M。NDA不等于订单推进。
- **P2 决策链支持**：已拜访关键角色，其支持或至少不反对参与，角色权限与持续联系可追溯。单个执行联系人友好不满足条件。
- **P3 教练建立**：已有1—2名能持续提供有效内部信息、提醒、解释或引荐的教练，并有实际可验证支持行为。教练离职、换岗或失联会触发复核。
- **P4 优选**：早期核投资/开发绑定及约束；晚期核正式优选、技术商务、竞争与审批。短名单不直接等于优选。
- **P5 中标**：早期保留条件订单/意向性质，核生效与承继；晚期核定标/合同/PO与CP。中标不等于合同已生效、融资关闭或可排产。

P必须绑定：当前决策主体、采购范围、有效时间和采购轮次（适用时）。开发商P4不能自动继承给新业主；也不能因转售自动判丢单。保留原主体位置，建立新主体的待核位置。

人物卡独立记录六槽位：身份层级、决策链位置、实际权限、信息价值、支持态度、实际行为。不能由CEO头衔推断定标权，不能由“很支持”推断教练或中标。

EPC代采分别展示EPC位置、业主批准条件和投资方设备认可；主要P归属由实际定标权限确定。联合决策保留双方位置和共同批准条件，不简单取最高P。

## 4. T：独立的设备采购进程

- T0 未启动：无有效设备RFx；仅有预告不升级。
- T1 RFI：正式市场摸底/供应商调研。
- T2 RFQ：预算询价或商务方案，必须区分测算目的与采购目的。
- T3 RFP：正式招标文件，核范围、截止日、评标和发起主体。
- T4 评标：评标、澄清、BAFO或优选谈判。
- T5 定标：中标通知、合同或PO；另核生效条件，无T6。

T可以跳步，不要求补造未发生事件；T4暂停仍显示T4，另标暂停原因/日期/恢复预计。回退或重招新增事件/轮次，保留原记录及失效原因。旧轮次T5不能压过新有效轮次T2。

采购范围并行时，为每个范围显示独立采购链；主链由用户明确指定，不用全项目最大T作为唯一阶段。全部轮次取消时显示“无有效采购轮次”，不伪装历史从未发生，也不自动判丢单。

PPA、merchant、消纳、融资是独立业务事件；可影响M和策略，但不直接改变设备T。发出一封预算报价也不自动表示客户已正式发起设备RFQ。

## 5. 当前有效位置与证据

资料定义的优先级：

```text
currentM = 当前仍有效的M核验值 ?? M申报值 ?? 原始M
currentP = 当前主体/范围内仍有效的P核验值 ?? P申报值
currentT = 当前有效采购轮次/范围内的T核验值 ?? T申报值
position = (currentM, currentP)
AI建议 = 独立对象，不参与以上优先级覆盖
```

缺P或M时显示“位置待确认”，不默认填P0/M0。原始M可用于暂定定位，但必须明显标“原始资料·待核”。仅部分维度核验时逐维显示状态；整个落点只在M、P均已核验且主体范围有效时用实线，否则用虚线。

核验值优先不等于永久有效：更新的相反证据触发“需复核”，保留旧值及其时效提示，授权人判定失效后再选择当前有效值。不能用陈旧核验值静默遮盖新变化。

信息性质F/C/I/U与管理状态是两个字段：

- F 可追溯事实；C 客户/销售口述；I 推断及理由；U 未知。
- 管理状态：原始、AI建议、销售申报、授权核验、需复核、失效。
- E0—E3只保留原始等级/空值，不从F/C/I/U自行推算；等级规则待补。

每条事实包含来源、日期、主体、范围、原话/摘要、关联实体ID及有效性。来源文档也可能过期或冲突；不把“有文件”等同“已核验”。

## 6. 对话右侧项目画像

保持之前“任务预览，完成一项打勾”的简洁形式。右侧默认约360—400px，复杂矩阵在宽侧抽屉展开，避免把36格缩成不可读的小表。

### 常驻摘要

1. 项目名称、关联客户、CRM实体类型及S阶段。
2. 大号当前位置，例如“M1 : P2”，下方“开发推进 / 决策链支持”；逐维标核验/申报。
3. P归属：“设备直采 · 当前开发商”，变化时突出提示。
4. 迷你M×P图：当前点、最近历史点，点击打开全景矩阵。
5. T独立横向节点：T0—T5，当前节点文字、采购轮次、目的与暂停状态。
6. 下一目标：“M1→M2 关闭核心开发障碍”“P2→P3 验证教练行为”，允许暂不升级、降低投入或只核实。
7. 当前3—5个关键事项，其他折叠；状态不能只靠颜色表达。

事项视觉语义：

- ✓ 绿色：此项业务条件已满足，并标口述/文件/核验状态。
- ◉ 蓝色：当前推进中，说明下一动作。
- ○ 灰色：未知/待确认，点击带入追问输入框。
- ! 橙色：阻塞、冲突或需复核。
- — 不适用：需原因、范围、确认人和复核条件，折叠展示。

另用较弱的“已核对”文字记录信息完整性，避免绿色勾选误解。例如“并网：已受理/待批；信息已核对”，核心RTB的“并网批准”仍不打勾。完成2/5表示事项完成数，不是项目成功率或阶段达成比例。

### 全景矩阵抽屉

横轴M0—M5，纵轴P0—P5，从下至上；各单元格展示PPT第1页策略名称与短动作。冷色表示投入，暖色表示风险；不把高M高P普遍当成越深越好。

背景颜色以原PPT视觉配置为最终依据；当前先保留语义类别，不凭文字自动编造精确色值或投入评分。M1×P4/P5用“规则待补”纹理。

当前点实心高亮并标独立T圆点，历史点小且空心；仅连接同项目的事件快照。待核点虚线，AI建议另用菱形标记。目标点用空心箭头且写“建议目标”，不能与已发生轨迹混淆。相同M/P下多次T事件显示叠点数量，点击按时间展开，不能覆盖旧事件。

点击格子看该格策略；只有点击“设为建议目标”才改变本地计划，不改变项目当前位置。点击历史点看当时主体、M/P/T、事件、来源及变更原因。

### 单项详情

显示条件定义、已做活动、已知事实、未关闭条件、责任人、下一节点和来源。来源统一收纳到“查看全部来源”，弹窗列客户、联系人、线索/商机、进展、商务活动、会议和文件；不新增大量“查看阶段证据”跳转。

支持“补充情况”“确认不适用”“提出修正”；产生M/P/T位置变动时弹出前后对照、主体、范围、依据和影响。销售确认申报与授权人核验必须分开，不能用通用“确认”按钮冒充核验权限。

## 7. 下一阶段指引

策略组合：**矩阵格核心动作 + M缺口 + P突破条件 + T窗口 + 主体变化 + 事实可靠性 + 可用资源**。最多输出8个可执行行动，默认优先3个；不为了填满8个生成无关工作。

每个行动必须有：目标维度、要获得的结果、执行对象、责任人、时间（未知则待定）、完成证据、资源与审批条件。缺失日期不自动编造承诺。

“定方向”：解释本格为什么优先做这件事、目标是推进M还是P、什么时候停止投入。

“识风险”：只突出影响当前判断或下一里程碑的未确认条件，如许可、Bankability、业主否决、转售承继或重招。

“递资源”：先诊断真实卡点，再匹配技术、投融资、EPC、收入/消纳、接待及其他集团资源；显示适用条件和审批人，不将资源候选写成可兑现承诺。

例如M1:P2 / T2预算询价：

1. M方向：向开发负责人确认并网申请、研究/批复及许可的准确状态，列清M2适用门槛。
2. P方向：请候选教练提供一个可验证的信息或完成引荐，记录结果，再考虑P3申报。
3. T方向：确认询价用于可研还是近期采购、由谁使用、何时转正式采购；T保持T2，不推算T3。
4. 资源：如卡点为并网方案，建议申请技术支持，先明确输入资料和工作边界。

推荐目标不固定为(M+1,P+1)。M4:P0应先核剩余采购入口并严格控投；M2:P4转售应先核新业主认可；M5低P应找真实剩余范围，而不是机械补齐P1—P5。

## 8. 对话更新闭环

1. 读取当前项目画像、用户私有观察、客户/项目CRM实体及最近事件。
2. 回答用户当前问题；仅提取本轮用户真实输入的新信息，不把系统提示或Agent自己的建议写成项目事实。
3. 为新信息绑定项目、主体、采购范围、发生日期和来源；含糊时先绑定待核，不跨客户拼接。
4. 更新事实候选及受影响事项；每轮只问1—3个最能改变判断的问题。
5. 普通事实补充可记录为用户口述并刷新信息完整性；不能由此自动修改M/P/T申报或核验值。
6. 如足以支持阶段变化，给出独立变更建议。用户明确确认后按权限写申报；授权核验独立操作。
7. 完成确认后更新位置、任务状态和历史快照；继续推荐下一关键事项，已知内容不重复问。
8. 用户不知道时停止追问，保留未知并建议下次向谁核实，不持续问卷式盘问。

示例：销售说“采购经理认可我们方案”。记录态度口述；问权限和具体行为，不升级P3。补充“发来评标时间并引荐技术总监”后，记录支持行为，建议P3申报，仍不能推断技术总监支持。

后台抽取可结构化输出 facts/proposedChanges/questions/actions/sourceRefs，但用户看到的是简洁结论、优先行动与必要追问。答案与追问同轮输出并流式呈现；追问按钮全文展示、点击填入输入框，由用户发送。创建任务/活动建议用另一颜色，点击才开草稿，不自动写CRM。

## 9. 项目画像与个人记忆

项目事实不应只存成某个用户的私有Memory.md，否则多人对同一项目各有“当前阶段”。建议分层：

- 项目共享画像：有权限的人看到同一管理位置、主体、采购轮次、核验事实与历史。
- 用户×项目观察：该用户口述、未核实线索、关注点及个人行动；合并到共享层需保留来源和权限。
- 用户记忆：沟通偏好和工作习惯，按日期更新，不影响项目业务事实。
- 用户×客户记忆：客户层关系和关注；不能直接当某项目的采购事实。

这是后续开发建议，不改变本地现有记忆权限。用户只看授权项目和自己的私有记忆；管理员查看范围按现有权限策略。Memory.md作为可读投影，结构化事实/事件是主记录，避免多个标题重复追加和并发覆盖。

建议Memory.md固定标题：项目标识、当前M/P/T与状态、主体与范围、阶段关键条件、事实与未知、下一里程碑、关注点、按日期变更摘要。每次更新局部字段，历史追加摘要，禁止把后台prompt当用户偏好。
