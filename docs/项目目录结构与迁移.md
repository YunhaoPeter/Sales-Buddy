## 知识与PPT边界

销售活动知识采用Markdown和结构化定义，归knowledge/sales；公开研究依据归knowledge/research。研究材料不是客户事实，也不代替公司的正式授权政策。

预制PPT是可版本化、多人共享的标准素材，连同预览及清单归assets/presentations。用户上传、针对客户生成或历史导出的资料属于私人运行数据，只放runtime/app/materials，通过SQLite索引，不混入预制PPT库。

销售文档由现有sales-knowledge/strategic-knowledge定义导出，guides为完整文档集，strategic是三类业务导航视图，保留既有版本与内容。使用npm命令复建，避免只改生成文件造成下一次导出覆盖。

## 路径配置

默认数据库为runtime/app/app.sqlite。Memory与个人素材默认放数据库相邻目录；环境变量DATABASE_PATH、MEMORY_ROOT、MATERIAL_ROOT仍可覆盖，不擅自移动工作区外的自定义路径。共享默认值见packages/paths.ts。预制PPT读取使用presentationLibraryRoot。

管理员API配置仍写本地.env，密钥没有迁移到仓库。新克隆按.env.example配置。已有环境先迁移，不能用空配置覆盖已有密钥。

## 测试生命周期

`npm test`、`npm run test:ci`、`npm run test:e2e`统一创建本次运行目录，通过TEST_RUN_ROOT传给子进程。所有SQLite、Memory和上传样例进入该目录。

- 成功：测试子进程结束后清理该次隔离数据，保留报告与截图。
- 失败：保留该次数据，控制台打印位置，便于排查。
- 手工直接运行测试文件：放runtime/test-runs/manual，不写项目根目录。
- 历史现场：本次只归档旧测试目录，未批量删除；以后需要回收空间可在确认不用后清理legacy。不要删除runtime/app来清理测试。

删除仅针对本次测试根目录，先检查最终真实路径仍在runtime/test-runs内。清理失败会保留现场并提示，不扩大删除范围。P11完整生成测试仍需要原有Artifact运行时。

## 本次迁移结果

本次搬迁226个目录或文件，其中旧测试目录192个。迁移前已用SQLite VACUUM INTO生成一致性备份。业务记录1135条、文档记录3192条，迁移前后数量一致；仅18条文档中的本地文件路径更新。对话正文、画像内容、用户上传和生成材料没有清空。

- 备份：runtime/backups/before-layout-2026-10-28T14-17-01-229Z.sqlite。
- 原data/backups中的历史备份：runtime/backups/legacy/。
- 迁移报告：runtime/reports/layout-migration.json。
- 原.build：runtime/archive/build-before-layout/。

迁移脚本默认只预览：

```sh
npm run layout:migrate
# 先停止本地服务，确认预览后执行：
npm run layout:migrate -- --apply
```

脚本拒绝覆盖已有目标、拒绝工作区外路径和符号链接目标；文件搬迁失败时尝试回滚已搬项目。数据库文件内的路径更新使用事务，不修改业务事实。若后续.env或文档路径更新失败，保留备份和已搬文件，可按日志继续处理，不能假定整个迁移具有跨文件与SQLite的原子性。

## 后续协作

新增功能继续走独立codex分支、PR合入develop、发布PR进入main。知识、PPT和原型属于版本化源文件；runtime的任何内容均不上传，CI每次从干净环境生成隔离数据。
