# 战略参谋对话界面与实体详情

更新日期：2026-10-27。

## 流式回答和状态

后端将在线模型返回的正文增量直接转为 answer_delta 事件，通过现有SSE连接发送给页面，不再等待整段生成和格式校对后集中发送。追问按钮仍来自同一轮回答中的私有代码块；增量过滤器保留可能尚未完整到达的围栏前缀，避免向用户展示解析内容。

页面状态随 run_phase 更新，包含读取CRM资料、补充核对资料、整理建议与推荐行动、校对答案、整理上下文追问。没有正文时显示加载圆点，生成中显示旋转指示和实时正文。若模型先补充工具查询，本轮临时文本清空后继续；正文格式校对完成时使用 answer_replace 同步最终内容，避免重复追加。

原有质量校对仍可在正文生成后运行；这一阶段会明确提示校对中。历史记录保存最终回答。

## 工作区

- 左侧：会话工作台，进入对象时默认隐藏，顶部按钮展开；保留任务步骤、执行状态和全部来源入口。历史回答可恢复该轮工作台。
- 中间：对话记录、动态加载状态、流式回答及输入框。
- 右侧：客户基本信息、当前项目和回答中提及的CRM记录。卡片最多展示12条，查看全部来源可检查完整检索清单。

右侧将“本轮读取”与“回答提及”区分处理，不把全部MCP结果直接堆成关键数据。客户卡片和业务卡片点击后打开详情弹窗。

## 实体详情

客户360 / CRM列表、右侧业务卡片复用结构化详情弹窗，覆盖客户、组织、联系人、项目联系人、线索、商机、线索进展、商机进展、商务活动、待办、客户资讯、会议记录、证据资料。

详情包含类型和名称、编号、中文字段、状态说明、业务内容、客户及项目归属、推进条件和关联记录。数组呈现清单，嵌套业务数据呈现分组，不把业务数据直接作为JSON展示。可从关联记录继续打开详情。内部执行日志仍保留技术数据查看方式。

接口：`GET /api/records/:id/detail`。先验证当前用户对主记录的访问权限，再返回同客户范围内的关联记录；跨客户请求仍拒绝。关联记录展示数量上限80条，并返回总数。

## 验证

141项单元与接口回归通过。新增浏览器用例覆盖左侧工作台位置及默认隐藏、客户与项目详情、13类实体详情接口、跨客户拒绝、增量及状态事件。

真实在线模型在隔离数据库中的HTTP验证结果：196次增量事件，首段约2093毫秒，完成约4525毫秒；私有追问代码块未出现在流式正文中。该时间是本次测试观测，不是服务性能承诺。结果文件为 advisor-stream-live-result.json。
