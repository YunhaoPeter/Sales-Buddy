# Daily 个人工作台

2026-11-02。设计阶段，仅使用虚构演示数据；不代表已接通客户邮箱或日历。

## 定位与参考

首页回答：今天最值得我关注什么、为什么、下一步怎么推进。综合个人待办、工作承诺、本人负责项目的背景与画像、客户邮件和日历，形成有限的行动队列。

参考 Amazon Quick Activity feed：https://docs.aws.amazon.com/quick/latest/userguide/activity-feed-desktop.html 。借鉴相关性排序、每日简报、建议行动、来源侧处理后的收起、日历与待办联动；具体销售场景与规则为本项目设计，不是对 Quick 产品能力的照搬说明。

## 信息与排序

1. 今日简报：浓缩今日目标、临期承诺及会议准备缺口，仅显示标题和业务描述。
2. AI提醒：默认最多展示3条，按紧迫性、业务影响、与本人职责相关性、证据新鲜度综合排序；不是按消息时间倒序。候选类型包括临期/逾期承诺、会前缺口、项目停滞、客户新诉求与范围冲突。
3. 我的待办：展示原有任务与截止时间，AI单独提出优先级、预计投入及下一步建议；允许人工调整。P1为当天硬截止或高影响阻塞，P2为重要推进，P3为可择机处理。逾期不直接等于最高优先级。
4. 今日日程：会议时间、对象、准备入口、加入入口；空档可推荐准备或专注时间，确认后才写日历。
5. 项目背景继续作为AI分析上下文，不再单独展示项目变化模块；来源细节在提醒详情中查看。

## 提醒对象与生命周期

每张Magic Cue卡片底部右侧增加“发起会话”，与创建日期同排。点击直接以当前卡片为上下文创建并发起AI会话，携带标题、描述、关联项目及用户有权访问的来源；不改变处理状态。P12.3 Magic Cue · 卡片发起AI会话（Wvee0）展示华东智造的上下文、用户委托、AI首轮建议和继续输入区，其他卡片按实际内容替换。此轮只完成Pencil入口关联及静态流程示例，未接入运行应用。

清单名称采用 **Magic Cue**，表达AI持续感知销售动态并提示下一步，不限定当天创建的提醒。仅保留“进行中 / 已完成”两个状态筛选Tab，默认进行中；切换后仅显示对应状态并回到列表顶部。当前Pencil展示静态选中态，不代表已实现运行时筛选。进行中的标识就是“标记完成”按钮，无额外状态标签；点击后归入已完成。点赞/点踩仅影响反馈，不改处理状态。P12.2 Magic Cue · 已完成Tab示例（ZBDNR）独立展示完成状态。

每条提醒应关联用户、项目、来源及来源时间、生成时间、理由、建议行动、关联待办、状态。以用户×项目×具体行动/承诺合并跨来源重复信息，保留全部证据。

- 待关注 → 已处理 / 稍后 / 不相关；已处理折叠且可查回。
- 标记提醒已处理不等于完成正式待办。来源侧邮件回复、任务完成、更新覆盖旧消息后重新核实，符合条件才自动收起。
- 同一任务已有待办则关联原记录，避免重复创建。新建议先进入确认态，确认后才成为正式任务。
- 邮件回复先生成可编辑草稿，用户审阅后通过邮件入口处理；不默认发送。
- 不自动改写CRM正式阶段或项目画像。沿用现有画像提案与确认机制。

## 可靠性与异常

- 仅处理用户授权、可访问的数据；按个人、客户、项目隔离。
- 显示来源与同步时间。邮件/日历未连接时给连接入口；同步失败保留上次结果并标为过期，不推断“无待办/无风险”。
- 区分来源事实、AI推断和待核实项；冲突并列展示。无依据不编造提醒。
- 首次使用先连接数据或手动添加任务；无待办显示创建入口；今日关注清空显示已处理结果与日程。
- 工作时间早/中/下午可更新简报，具体节奏允许设置；新变化才提醒，避免重复打扰。
