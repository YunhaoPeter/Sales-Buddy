# 对话建议与CRM创建按钮
日期：2026-10-25。

## 交互
蓝紫色“建议提问”按钮继续在当前会话内运行Agent，例如生成推进计划、准备客户沟通、整理下一步待办、准备商务活动。它们查询对象信息、进展、联系人、已有任务/活动，并返回分析或计划，不创建草稿或CRM业务记录。
绿色“创建类建议”按钮明确包含创建含义，例如创建待办草稿、创建商务活动草稿、创建进展记录。点击后才出现可编辑草稿；最终确认后通过MCP写入。颜色、分组文字及图标共同表达区别。

## 具体行为
- 整理待办：汇总状态、证据缺口、已有任务及后续建议，列出优先顺序、责任角色、产出和完成判定；不把相似标题直接判为重复。
- 准备活动：汇总最近沟通和联系人，提供活动目标、参与角色、会前资料、议程、关键问题、话术和会后跟进；未知人名及时间保持待确认。
- 创建入口只在对应建议结果后出现。已有精确同名未完成任务先核对/复用；没有新增候选时不提供待办创建入口。
- 创建任务草稿前再次通过MCP读取已有任务；只生成本轮建议中明确新增的项，字段先校验，再持久化为待确认草稿。
- 客户级与项目级任务保持对象作用域；客户下不同项目不能只凭同名认定重复。
- 历史prepare_task/prepare_activity按钮也按新提问语义执行；旧创建进展按钮按创建颜色展示。客户端不能把普通提问按钮伪造成创建动作。
- 按钮处理中显示状态并禁用重复触发；继续提问采用当前页面选择的运行模式。草稿时间是建议值，用户需核对负责人、日期及实际排期。

## 验证
自动测试覆盖：两类准备按钮不产生草稿和CRM写入；明确创建生成当前回答对应草稿；创建不等于写入；跨用户及伪造动作拒绝；已有任务覆盖时不展示虚假创建入口。
浏览器覆盖：待办建议→独立创建→确认写入→CRM回查；商务活动准备→无表单/无写入→绿色创建→草稿；两种颜色不同。
真实模型验证已通过：历史活动按钮只生成计划，明确创建按钮才生成待确认草稿，CRM业务记录数量不变。见action-intents-live-result.json；不是完整30题能力验收。
