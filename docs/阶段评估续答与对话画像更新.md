# 阶段评估续答与对话画像更新

更新日期：2026-11-01。

## 评估流程

M/P/T基础问题每轮仍使用“提交”完成核实。基础问题提交后，无论进入结果还是延伸追问，弹窗右下角提供“进入下一阶段”；最后一个待核维度显示“完成更新”。M、P可不回答延伸问题直接前进，跳过的问题记录为待核信息，不伪造成已确认。

“进入下一阶段”仅推进当前评估草稿，不修改有效画像。“完成更新”代表用户最终保存本次所选阶段与已回答事项；仍有未知条件时保留独立核实结论。用户在T维度之前离开，仍须主动暂存才持久化续答记录。后端拒绝在首次提交基础问题之前直接跳维度。

阶段选择保留“保存选择，进入核对”和“重新评估全部维度”，采用有间距的可换行按钮组。保持原阶段也允许复核，不再要求必须改成其他阶段才能进入核对。

## 画像答案回填

相同阶段的基础问题，按固定事项键从用户自己的当前项目画像读取最新描述和状态，回填到答题卡，并提示可修改。空白事项保持空白，不将“尚未明确”提示语当作销售回答。切换新阶段不套用旧阶段答案。

回填内容只是可编辑输入，不自动重新保存或声明为本轮新事实。用户提交并完成更新后才写入新版本。手动暂存的半填草稿继续优先恢复。

## 在聊天中更新画像

点击“根据本次对话更新画像”后，在当前会话发起专门的Agent运行：

1. 读取本次会话中的真实销售陈述、有效项目画像和关联CRM/知识上下文，展示分析中的加载状态。
2. Agent分析明确事实与现有画像差异，在聊天正文说明更新依据和不足。
3. 同一条回答附带可勾选的画像建议卡：固定事项、原描述、新描述、确认状态及用户原话。此时只保存提案，不更新画像。
4. 用户点击“确认更新所选事项”，调用应用内`update_project_profile` Skill，校验所有权、事项范围、所选变更及画像版本，再保存。
5. 聊天记录确认操作和保存结果，侧栏刷新，项目画像Markdown及历史版本同步；重复确认不会重复更新或重复产生确认消息。

这里的Skill为应用内部有确认约束的更新执行函数，不是模型可自由调用的任意写入接口。模型只能提出候选变更，不能绕过用户确认。阶段变化仍通过阶段核对流程处理，不因事项更新自动改变M/P/T。

对话进行中暂时禁用画像分析入口，避免上一轮刚结束时点击动作丢失。聊天历史中的建议卡可重新查看，已确认的建议显示保存状态。确认结果也有完整的回答与工作台记录，支持重新进入会话。

## 验证

覆盖基础题未提交不能跳维度、延伸追问可跳过、缺口保留、同阶段答案回填及编辑、新阶段不套用旧答案、确认前画像不变、Skill所有权与空选择校验、版本控制及幂等、确认消息和工作台持久化。浏览器覆盖M/P/T完成更新、同阶段复核回填、按钮不重叠、对话中的建议卡及确认后侧栏刷新，以及原有待办和知识库旅程。
