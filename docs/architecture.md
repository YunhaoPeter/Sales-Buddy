# 实际架构（v0.1）
日期：2026-10-25

- React/TypeScript/Vite前端；Express/TypeScript后端。
- 一个后端进程承载应用API与 /mcp；Vite开发中间件使用同一3001端口，生产静态文件来自dist/web。
- CRM实体逻辑独立，SQLite统一records表保存类型、客户、业务关联及JSON字段。触发器和CHECK约束区分线索、商机及两种进展。
- Agent的业务读取走官方SDK的真实Streamable HTTP MCP Client→Server链路。查询不能靠模型参数切换用户。
- 每轮Answer/Workbench/来源快照单独持久化。后台日志分别保存应用run和实际MCP调用。
- Memory用结构化条目/版本作为事实源，生成Markdown投影；私有问题不提升为共享背景。
- replay用规则和模板组织回答；live使用Chat Completions流式工具调用。两种模式明确标识。
- 在线模型已配置，代表性回答、草稿及语义记忆已验证；完整业务验收待完成。

## 首版与方案的工程差异

1. 用单个records物理表和类型约束简化Mock，不是生产CRM完整表结构；实体及主键仍独立。
2. 管理后台为一个SPA中的页面，不另外部署服务。
3. 工作台动态分组，CRM、知识、Memory同一个来源协议。
4. 初始阶段评估使用结构化演示证据字段；在线模型同时读取进展原文。不是通过阶段预测成交率。
5. 知识主索引为30份原创内部活动指引；公开摘要只保留历史文件，不进入主库检索。企业授权及具体国家适用性需专业审核。
6. 批量任务共用确认卡，可勾选、编辑并逐项提交；部分成功保留回执，重试复用确认版本。
7. 当前自动化验证覆盖103个用例和浏览器主链路；并非全部企业业务验收。


## v3补充
角色规范从prompts/战略参谋.md加载。工具循环的中间叙述不进入正文；最终回答经风格检查后发布。后续问题独立后台生成和缓存，失败不阻塞主回答。
Memory采用用户/用户×客户/用户×项目三种私有键，只有有效摘要按相关性进入模型；旧共享背景和来源不明条目归档。新消息记录真实输入、点击追问、工具快捷及系统来源，提取以用户原文证据为准。
