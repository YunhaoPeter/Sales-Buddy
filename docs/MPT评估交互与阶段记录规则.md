# MPT评估交互与阶段记录规则

更新日期：2026-11-01。

## 阶段记录与核实结论

用户选择并最终确认的 M、P、T 是项目画像的有效阶段。AI的核实结论另存为“符合”“信息不足”“存在冲突”，不会把用户阶段改成空值。未知事项、适用性说明及规则缺口继续保留，后续对话将结合这些信息给予建议。CRM S0–S8阶段保持独立。

首次评估按 M → P → T；修改阶段仅核实发生变化的维度。每个维度提交不立即改画像，最后“确认并保存项目画像”才写入新版本。重新评估未修改维度保留原核实结论。

## 必需条件与可后补信息

“必需条件”是判断阶段定义成立的核心依据，不是提交门槛；不清楚、未提供或存在冲突仍允许用户提交并最终确认阶段。“可后补”是进一步推进业务所需的资料、执行细节，不会仅因为缺失而强制否定阶段。界面逐题展示类别。

|阶段|必需核实主题|可后补信息示例|
|---|---|---|
|M0|项目主体、应用规模、实际开发动作|下一步负责人、原始消息日期|
|M1|土地控制、并网实际节点、核心许可状态|当前障碍的具体对接人|
|M2|核心RTB文件与未关闭条件|自持/转售、未来投资人、选型认可、资金收入路径细节|
|M3|融资实际卡点、收入及承购安排|成本输入、设备融资认可要求、采购组织细节|
|M4|NTP先决条件、合同生效状态、开工指令授权主体|付款担保细节、交付接口与剩余范围|
|M5|实际施工与交付进度|我方合同、剩余供货、变更验收付款细节|
|P0|项目身份、是否已建立回应|信息日期、联系渠道|
|P1|回应者及其角色|首访、决策链全貌、下一次会面|
|P2|影响/决策权限、实际支持范围|后续信息或引荐能力|
|P3|具体支持行为、时间与可验证结果|信息时效、岗位与主体变化|
|P4|书面形式、绑定性质、批准主体、未来业主/EPC认可、重采与未决约束|更详细的执行资料|
|P5|中标确认主体和范围|合同生效、融资/NTP与交付条件|
|T0|是否存在设备采购活动、是否发出RFx|窗口与负责人|
|T1|发起主体、RFI目的与研究筛选内容|具体执行资料|
|T2|预算或正式报价性质、范围口径及决策主体|PPA及投资决策关联细节|
|T3|正式招标文件与要求、招评定标签约角色|更多执行资料|
|T4|实际评标节点、是否重新询价或招标|偏差与竞争替换细节|
|T5|正式结果、选定主体、范围有效期与先决条件|更多执行资料|

这里的分类用于现有知识基线，不额外发明自动升级规则。M1×P4/P5的SED规则继续标记待补；M3不要求融资已经关闭；T5不等于我方中标。

当前基础问题分类在 `packages/mpt-assessment.ts` 按阶段的问题顺序配置，问题正文与定义来自每次评估固定的知识版本。业务调优若调整基础问题顺序或增加问题，应同步核对分类及回归测试；现有Excel列未改动。动态追问全部应针对必需条件。

## 问答交互

1. 选择阶段后展示基础问题卡片，提供上一个、下一个问题。翻页保留本窗口输入。
2. 点击“提交”统一分析本轮已填回答，允许跳过未掌握的信息；未作答列入待核缺口，不生成虚假的销售原话。
3. 结合所选阶段定义、判断规则、真实回答、项目画像以及关联项目/客户/联系人/组织数据核实。
4. 如仍有关键缺口，直接列出本轮延伸问题并呈现首个答题卡，不再要求额外点击“开始追问”。
5. 没有关键缺口或达到轮数限制后展示核实结果。点击“提交”进入下一维度，最终统一确认。

## 精简追问

- 必须能说明该问题影响哪个阶段核心条件；背景资料与执行细节归入后续补充建议。
- 已明确的事实不重复问；用户明确不知道的同一问题不换个说法反复问。
- 优先真实冲突，再核实影响阶段成立的关键缺口；一题聚焦一个决定性事项。
- 每轮最多3题，最多2轮延伸追问；“符合”不再触发延伸追问。
- 达到轮数后保留待核事项及原因，允许用户确认阶段，不无限追问。
- 条数与轮数及文字去重由程序保证；语义优先级由模型结合规则判断，需持续用业务案例评估。

## 暂存与缓存

翻页仅使用前端内存缓存。提交用于当前评估会话的分析，不自动把续答草稿写入数据库；工作中的状态暂存在服务内存。只有点击“暂存，稍后继续”才保存续答位置、已提交回答、半填草稿及分析结果。以后重新打开恢复最后一次手动暂存的版本。直接关闭或刷新不保存新增输入；原来的手动暂存仍保留。最终确认保存正式画像及评估记录。

兼容历史已自动暂存的评估记录，仍可继续；不会删除或迁移用户已有画像数据。未暂存的工作状态在服务重启后不保留。

## 验证范围

服务测试覆盖阶段声明与核实分离、缺少必需信息仍能保存、可后补未知不强制否定、手动暂存与半填恢复、未暂存修改不覆盖存档、权限、规则待补、去重/轮数限制、画像版本及CRM隔离。浏览器验证覆盖翻页缓存、手动暂存续答、MPT完整确认和原有矩阵/待办/知识管理旅程。
