# 猜你想问：用户委托生成规则

更新日期：2026-11-01；建议协议版本6；回答规范版本5。

## 三类内容分开

- 正文主动核实：Agent向销售确认真正阻塞判断的事实，最多3个。销售不知道时给核实路径，不反复盘问。
- 正文下一步行动：说明目标、对接角色、沟通方式和期望结果。创建任务、活动或进展仍使用独立创建按钮与确认草稿。
- 猜你想问：销售希望委托Agent继续完成的工作，点击只带入输入框，用户可以编辑后发送。

“Hassan是否最终签批人”属于主动核实；“帮我查询Hassan在CRM中的资料及历史活动”属于用户委托。“帮我准备核实审批路径的话术”也属于用户委托，能在销售尚不知道事实时继续提供帮助。

## 同轮生成

主回答末尾沿用隐藏的` salesbuddy-followups `代码块，不增加第二轮模型请求。每条包含完整请求、建议方向和关联实体。建议方向为查询、分析、沟通准备、计划、资源或画像提案，不要求机械凑齐六类。

结合本轮问题、回答结论、已有CRM记录、画像重点事项缺口挑选3–5条有价值的委托。有效工作不足时允许少于3条，不用固定模板补数量。保留完整文案，不为按钮宽度截断内容。

## 校验

逐条检查格式；单条损坏不影响其余建议。过滤明显向销售索取事实的句式、直接创建或不支持的发送操作。保留查询和准备沟通的表达，以及“如何推进/如何核实”等销售请求指导的问法。“更新建议”不应被误判为“新建”。

每条必须关联当前对话对象，其他实体必须属于有权限、已实际读取的CRM来源。去除与本轮原问题完全重复及文本重复的建议，无关数据清理不入选，最多展示5条。

这些程序校验约束数量、格式、角色表达和实体范围；语义相关性、是否确实值得继续讨论仍依赖主模型，需要持续通过真实业务样例调优。过滤后不足时不另起模型补齐；正文和创建按钮不受影响。

## 能力边界与历史

联系人查询以已有CRM资料为准。公开背景不能证明内部签批权；资源缺联系人时不编造。画像方向仅整理当前客户/项目画像更新提案，不直接更新，也不创建联系人个人画像。

历史主回答、用户输入、创建记录均保留；旧版本建议不按新规则自动重新生成或继续展示，新的回答使用新版本。用户可围绕历史内容再次提问，获得当前规则的建议。

## 验证

覆盖用户给出的三类事实追问反例、六类用户请求、创建/发送隔离、混合输出逐条过滤、越界实体、完整长文案、同轮零额外模型请求、点击预填及用户手动发送。另用合成项目实际调用已配置的在线模型，核对建议为用户委托且关联当前项目；该样例不代表所有真实销售场景的准确率。
