# 战略参谋回答与个人记忆 v3 实施报告
日期：2026-10-25。状态：本地版本已实现并验证；仍需真实销售业务评审。

## 本次结果
1. prompts/战略参谋.md成为回答规范单一来源。默认约1000字、最多8个行动，先回答问题，强调找谁/做什么/产出。避免重复列步骤和行动表、证据盘点和未请求的英文版。问候或仅确认偏好保持简短；用户明确要求详细时按需展开。工具中间文字不拼接到最终答案。
2. 发布前检查可见字数和行动数量，必要时最多两次编辑压缩。首次真实检查发现1646–1934字及多组重复结构，修正后推进881字、价格1043字、待办933字、活动1025字；跨客户样例1380字。字符统计排除JSON协议字段，保留表格单元格。
3. 后续2–3题使用本次问题、本轮答案、真实实体和有效个人记忆生成。固定四项能力改到输入框常用工具。问候/仅确认不强推业务追问。推荐缓存版本升级，历史正文保留、旧固定问题不再直接显示。
4. 追问后台补齐，不阻塞主回答；失败保留主答案并可单独重试，普通GET不会无限重试。蓝紫色追问、绿色创建草稿流程保留。
5. 记忆入口对所有用户开放。普通销售及经理只看自己的；管理员可筛选全部用户。管理员的Agent对话仍只读取管理员自己的有效记忆，不偷用销售私有记忆。

## 消息来源与记忆
新消息保存user_input、suggestion_click、tool_shortcut、system或legacy_unknown来源。用户可见内容和系统执行要求分离，来源用userMessageId关联。系统快捷操作不生成长期偏好；用户点击追问最多用于当前对象关注。真正的用户明确长期偏好，包括其主动要求的格式，可按原话保存；不能只因出现JSON字样就当系统来源，也不能将后台JSON要求误记成用户偏好。

两个页面模块：用户记忆，以及客户/项目记忆。底层三种私有键：用户、用户×客户、用户×线索/商机。项目和客户按明确范围关联，不把子项目参数扩散至整个客户。CRM正式阶段与用户新陈述分开，用户声明保留待核实身份，不回写CRM事实。

个人MD固定为稳定特征、长期偏好、待确认倾向、日期变更记录。对象MD固定摘要、阶段变化、我的关注、未决问题、下一步、待核实陈述和日期记录；同类标题只出现一次。日期及日志使用真实北京时间。模型只接收相关摘要，不接收完整日期日志、停用条目或未确认个人倾向。

每条保留原话、消息ID、来源时间与版本。重复行为至少两条来源才形成候选，不覆盖已明确偏好，确认后才生效。纠正、停用、恢复、候选确认、补充和回滚均记录版本与原因；停用有排除记录，较早的异步结果不能覆盖较新的人工纠正。

结构化数据库为事实源，Memory.md为文件投影；投影失败进入原有重试队列。用户可下载MD，不能任意破坏整份文件结构。个人记忆不是生产授权来源，不能覆盖系统权限或CRM创建确认。

## API与兼容
- GET /api/memories、/:id、/:id/versions、/archives：所有者或管理员，并检查对象权限。
- PATCH /api/memories/:id：版本与原因校验，add/correct/disable/restore/confirm/rollback；不接受任意所有者或文件路径。
- GET /api/answers/:id/suggestions、POST /:id/suggestions/retry：按回答所有权校验，元数据独立更新。
- 原管理员记忆接口保留兼容，但调用相同私有权限规则。创建草稿仍校验原回答和受支持工具，不能用动态问题伪造写入。

## 使用
刷新本地应用。对话正文下看继续讨论；输入框左下常用工具可整理待办与准备活动。侧栏记忆管理提供用户记忆和客户/项目记忆；修改时填写原因，管理员可筛选用户。后台提取可能晚于正文完成，稍后点击刷新记忆查看。
