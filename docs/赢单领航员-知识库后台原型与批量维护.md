# 赢单领航员：知识库后台与批量维护原型

日期：2026-11-01。范围为Pencil原型、交互规划及模板规格；本次没有开发上传、导出、校验或发布接口，也未实际导入知识内容。页面内条数、版本、审核与回归结果均为状态示例。

## 1. 入口与页面

管理员设置P10.29顶栏新增“赢单知识库管理”，进入P10.114。新画板位于赢单领航员组件区下方，新增“06 赢单领航员 · 知识库运营后台”分区，按从左到右、从上到下阅读。

- P10.114：知识库总览，七类模块、发布/草稿指标、最近更新批次、导出与上传入口。
- P10.115：模块清单，按模块、业务视角、M/P/T及状态筛选；搜索、分页、选中导出、模板下载。
- P10.116：条目结构化编辑，展示稳定ID、适用范围、阶段、定义、规则/问题引用、维护与审核角色、来源定位及AI可读预览。
- P10.117：批量导出，选择模块、发布版本、是否含草稿、依赖及联系字段，下载标准包或空模板。
- P10.118：上传更新，ZIP/XLSX、更新说明、基准版本、增量匹配及草稿方式。
- P10.119：校验结果，新增/修改/停用及阻断错误，下载错误清单、重新上传；修复后的后续状态另由120演示。
- P10.120：逐项差异，选择条目、原值/新值、采纳字段、理由与方法论依据，保存草稿或提交审核。
- P10.121：业务审核及发布，展示字段、引用、基准版本、业务审核、回归检查与影响范围。
- P10.122：发布历史，当前版本、历史清单、版本导出及回滚入口。
- P10.123：回滚确认，来源、新发布版本、原因、恢复范围、检查及确认。

所有页面复用既有后台的224宽导航、64高顶栏、紫色主操作、卡片与表单样式。页面ID与模块选择绑定为原型元数据；实际状态筛选、文件下载、上传及任意模块动态渲染仍待开发。

## 2. 七类模块

1. 阶段定义：M0—M5、P0—P5、T0—T5。
2. 阶段判断规则：适用条件、必需事实、判断、未知与冲突处理。
3. 画像事项与活动：画像字段、业务动作、责任、产出和关闭标准。
4. 追问问题：触发、跳过、选项、答案映射与后续分支。
5. M×P策略：36格基础打法、投入、下一里程碑与资源类别。
6. 风险规则：触发信号、影响、核实、缓释及关闭条件。
7. 资源能力与联系：支持能力、地区、前提、材料、归口与员工引用；员工目录和能力条目分别维护。

“定方向、识风险、递资源”作为跨模块标签，不重复复制同一知识。模块切换复用清单、详情、导入和导出组件。116以M3定义为代表性实例，实际编辑字段由模块Schema决定。

## 3. 批量文件规格

标准ZIP包建议包含：

```text
manifest.json
modules/
  stage_definitions.xlsx
  assessment_rules.xlsx
  portrait_activities.xlsx
  questions.xlsx
  matrix_strategies.xlsx
  risk_rules.xlsx
  resource_capabilities.xlsx
content/
  <record_id>.md
schemas/
dependencies.json
```

员工目录为受限的单独清单或受控数据源，默认不混入普通知识包。导出联系字段需要单独权限和明确勾选。模板文件由未来系统生成；本次只定义包格式和原型。

### 公共字段

`record_id、module_type、title、pillar_tags、entry_version、base_entry_version、operation、release_version、applicable_regions、project_types、review_status、owner_ref、reviewer_ref、source_reference、content_path、change_reason`。

- record_id稳定，不以名称作为覆盖依据。
- operation为新增、更新或显式停用；包中未出现的条目不删除。
- release_version为发布快照；entry_version为单条知识版本，两者分开。
- 对已有条目提交更新时携带base_entry_version，避免基于旧导出覆盖他人的新修改。
- MD由content_path关联，不能用上传文件名直接生成知识身份。

### 模块专属字段

阶段定义：`axis、stage_code、definition、applicable_scope、required_rule_refs、question_package_refs、activity_refs、common_misjudgments`。

判断规则：`target_axis、target_stage、applicability_conditions、required_fact_keys、condition_expression、acceptable_sources、missing_policy、conflict_policy、exception_refs、question_refs`。

事项与活动：`fact_keys、objective、responsible_role、steps、required_inputs、expected_output、completion_criteria、dependencies、risk_refs、resource_refs`。

追问问题：`related_rule_id、fact_keys、trigger_conditions、skip_conditions、question_intent、template、options、answer_mapping、followup_branches、priority、stop_condition`。

矩阵策略：`M、P、strategic_goal、investment_guidance、priority_activities、key_risks、resource_categories、next_milestone、review_or_exit_conditions、exception_rules`。

风险规则：`trigger_conditions、applicable_stages、affected_objective、severity_rule、verification_questions、mitigation_activities、closure_criteria、resource_refs`。

资源能力：`category、capability、prerequisites、exclusions、required_materials、expected_output、department、employee_refs、availability_status、last_verified_at、access_level`。

复杂数组和条件可由模板的子表或受约束JSON单元格表达，必须提供字段说明与枚举，不让业务人员编写任意可执行表达式。不同模块使用各自Schema版本。

## 4. 上传与差异确认规则

上传先创建批次，不直接写入有效知识。依次执行：

1. 包格式、Schema版本、大小及文件路径检查；拒绝异常路径和无关文件。
2. 必填字段、稳定ID重复、枚举、结构及模块类型检查。
3. 基准发布和单条版本冲突检查。
4. 规则、问题、活动、画像字段、资源等引用检查；停用条目需检查是否仍被引用。
5. 正文与结构化关键字段的一致性检查，冲突不静默选择其中一个。
6. 生成新增、修改、停用和未变化清单；显示逐字段原值、新值、理由。
7. 用户选择采纳范围后再次验证依赖，形成待审核草稿。

阻断错误例如缺少ID、未知枚举、引用缺失、版本冲突。业务提醒例如审核材料不足或适用性待核；不得把业务提醒当成审批通过。M1×P4/P5 SED及完整E等级定义待补，不能上传一条任意表达式就变成正式判定规则。

119中的“查看修复后的差异样例”是原型场景连接；实际系统必须修复并重新校验，不能绕过错误进入发布。

## 5. 审核、发布与回滚

权限区分查看、维护、导入、导出、业务审核、发布和回滚。当前页面使用管理员示例，但不能据此让所有普通销售修改正式方法论。维护和审核分别留痕，资源员工字段另做访问控制。

发布前检查Schema、版本、引用、业务审核和回归案例。知识包和检索索引就绪后再切换在线发布；失败时保留原在线版本，允许重试。

发布后：

- 新请求使用新发布版本，并记录实际知识引用。
- 正在进行的评估保留已绑定版本及用户答案，必要时提示补问。
- 已确认画像不自动变更阶段；判断标准变化时标记受影响项目待复核。
- 重要规则变化时重新检查待确认的画像提案。

回滚恢复历史知识内容，生成新的发布记录。例如将v1.4.0内容恢复为v1.5.1，保留v1.5.0审计。索引成功后生效，不回滚CRM、对话、任务、项目画像和私有记忆。
