# 赢单领航员：按模块Excel维护知识清单

日期：2026-11-01。此版替代此前的知识更新包及审核发布设计。当前交付为原型和填写规范，不开发实际导入导出功能。

## 1. 维护方式

选择模块 → 查看知识清单和填写规范 → 下载本模块Excel → 填写或修改 → 导入Excel → 确认清单 → 自动保存新版本。

每次只维护一个模块。Excel按该模块完整清单导入，确认前显示知识条数、调整内容及未保留的原内容。其他模块保持原样，原清单保留为历史版本。

只使用本模块Excel中的清单字段，不要求附带PPT或其他文件。每份模板包含“知识清单”和“填写说明”两个工作表。导出也是本模块Excel清单，不打包成知识更新包。

## 2. 公共填写规范

- 一行一条知识，一列一项内容；使用模板列名，不合并单元格。
- 星号字段必填。选填项没有内容可留空；业务事实不明确时写“待补充”，不要编造。
- 阶段写M0—M5、P0—P5或T0—T5；多个阶段用中文顿号分隔，不能只写“前期”“后期”。
- 地区写欧洲、北美、中东、亚太或更具体国家；确实通用时写“通用”。
- 先描述条件和动作，再解释原因。避免只有“加强沟通”“关系良好”“项目成熟”等笼统措辞。
- 步骤、选项等多项内容在同一单元格内换行，可用1、2、3编号。
- 涉及审批、融资、订单时说明实际状态和条件，不混用申请、受理、批准、签署和落实。
- 使用直接的业务知识文本；不填写“见某PPT第几页”代替内容。

## 3. 阶段定义清单

用于说明每个M/P/T阶段的含义。

字段要求：

- **所属维度***：选择M、P或T。
- **阶段***：与维度一致，如M1、P3、T2；每个维度和阶段一行。
- **阶段名称***：简明业务名称，如“开发推进”“教练实际行为”。
- **阶段说明***：完整说明该阶段的业务状态，建议1—3句话。
- **判断要点***：列明支持阶段判断的关键事实，建议2—5点。
- **常见误判**：说明容易混淆的情况和不能直接认定的结论。

示例：M / M3 / 投资级RTB推进。说明围绕可融资收入、可靠预算、合同、采购和风险分配推进，融资尚未落实不单独否定M3。

## 4. 阶段判断规则清单

用于说明如何结合项目情况进行阶段判断。

- **规则名称***：能体现要判断的问题，如“核心RTB条件核对”。
- **适用维度***：M、P或T。
- **目标阶段***：本规则用于判断哪个阶段。
- **适用条件***：什么项目、情形或采购模式需要使用。
- **应确认事项***：销售需要核实的关键内容。
- **判定标准***：何种具体情况支持或不支持该阶段。
- **信息不足时如何追问***：需要继续问什么，不能把未知直接判成不满足。
- **例外说明**：特殊情况或尚未确定的规则；没有可留空。

规范：条件与核实动作分别写清，不以完成事项数量或比例自动判阶段。业务规则尚未明确时写“待补充”。

## 5. 画像事项与活动清单

用于定义阶段中应该了解什么、开展什么活动。

- **活动名称***：一个具体事项或活动，如“并网条件核对”。
- **适用阶段***：可列多个M/P/T阶段。
- **活动目的***：说明要解决什么业务问题。
- **具体动作***：写可执行步骤，不只写活动名称。
- **找谁开展***：写客户或内部责任角色；知道具体人员时可补充姓名。
- **需准备资料**：列出开展活动需要的输入材料。
- **应形成结果***：如剩余条件清单、评审安排或融资初筛需求。
- **完成判定***：说明怎样算达成，不用“已经沟通”代替。

规范：按“找谁、做什么、拿到什么结果”填写。活动已开展与业务条件已满足分开判断。

## 6. 追问问题清单

用于让Agent围绕当前项目缺口继续了解信息。

- **问题名称***：简明概括核实目的。
- **适用阶段***：在哪些阶段使用。
- **什么时候问***：如批复已取得但附加条件不明。
- **问题内容***：可直接向销售提出的完整问题。
- **选项与含义**：需要选择时逐行列出选项及解释；开放问题可留空。
- **不同答案如何追问**：对关键答案分别说明下一步要了解什么。
- **什么时候结束***：什么信息已明确后无需继续问；已有可靠答案时也应说明跳过。

规范：一个问题聚焦一个关键事项。选项之间有清晰区别，允许保留未知，不能反复盘问同一个已回答问题。

## 7. M×P策略清单

用于说明不同项目位置的推进打法。

- **M阶段***：M0—M5。
- **P阶段***：P0—P5；每个M与P组合一行。
- **当前目标***：本位置优先解决什么。
- **投入建议***：例如观察、选择性培育、重点投入或控制投入，并说明原因。
- **关键动作***：建议1—3个最重要动作。
- **风险提醒**：与该位置实际相关的风险。
- **可寻求资源**：写支持能力或部门，不承诺资源已获批。
- **下一里程碑***：下一项应取得的业务结果。

规范：不能36个格子都写同一套销售建议。T作为独立采购进程在对话中结合，不要求人为复制全部M/P/T组合。

## 8. 风险规则清单

用于发现问题并指引核实与应对。

- **风险名称***：具体、可理解的名称。
- **适用阶段***：哪些阶段可能出现。
- **触发信号***：哪些可观察情况需要关注。
- **可能影响***：影响项目落地、订单位置、采购或履约的什么方面。
- **需要核实的问题***：不确定时向销售确认什么。
- **应对动作***：找谁采取什么行动。
- **解除或关闭标准***：怎样确认风险已解除或得到控制。

规范：信息未知不是已证实失败；应对后仍有条件的，在描述中保留，不简单标为全部解决。

## 9. 资源能力与联系清单

用于回答“内部能提供什么支持、找谁、准备什么”。

- **资源名称***：清楚表达能力，如“并网技术支持”。
- **资源类别***：信息、技术、金融、接待、关系协调、合同、交付等。
- **适用地区***：地区或国家，通用能力填“通用”。
- **适用阶段***：适用的M/P/T阶段。
- **能支持什么***：具体可交付的支持内容。
- **使用前提***：客户或项目需具备哪些条件。
- **准备资料**：申请支持前的材料。
- **对接部门***：实际归口部门。
- **联系人姓名**：当前有效人员；未知写“待补充”。
- **工号**：企业实际工号，不自行编造。
- **联系渠道**：如COME3.0或企业允许的业务联系方式。

规范：真实填写支持边界，不将金融协调写成融资保证，不将介绍关系写成审批保证。维护联系人变动时更新本模块清单。原型中的人员均为示例。

## 10. 导入确认与版本回退

导入前显示本次文件、本模块、当前条数、导入条数和内容变化。必填缺失、阶段写法错误或重复行直接用Excel行号和字段名提示，修正后才能更新。

导入以完整清单替换当前模块：如Excel未保留原有知识，必须在确认页列明，不能悄悄移除。用户确认后自动生成新版本，不增加审核发布操作。

版本记录显示第几版、更新时间、维护说明和知识条数。可查看历史清单、下载对应Excel、确认恢复该版。恢复也保存为新版本，历史继续保留；只影响本模块知识，不回退客户、对话、待办、项目画像或私有记忆。
