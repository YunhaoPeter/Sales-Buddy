# 最近沟通、对话日志与布局修复
日期：2026-10-25。

## 原因与修复
1. recent接口原先排除了customer Scope，现按当前用户+对象类型+对象ID聚合，包含客户、线索与商机。只统计有提问的会话，空会话不占最近列表；排序使用真实最近提问时间。客户级讨论不自动归给某个子项目。
2. 首页展示最近问题、会话数、轮数和结果；继续对话使用该卡片的原会话ID，不被新建空会话抢占。进入首页重新读取最近记录。
3. conversation_logs每轮以runId独立存储问题、模式、对象、会话、问题消息ID、回答ID、实际请求/完成时间、MCP次数和结果。失败/取消/重启中断保留记录。旧run补建日志，旧时间明确标记legacy_record，不捏造历史真实时间。
4. 当前用户通过GET /api/conversation-logs分页读取自己的授权日志；首页“对话日志”可查看并打开原会话。用户相互隔离。
5. 会话及新消息使用真实时间；CRM演示业务时钟保留用于种子业务情景。旧会话标题在读取时以首条提问改善识别，原消息保留。
6. 侧栏history-list独立滚动，主区域在对话模式固定高度；中间消息区及右工作台分别滚动。自动滚动仅更新消息容器scrollTop，不再调用可能移动祖先页面的scrollIntoView。

## 验证
客户级对话→首页出现→刷新保留→日志原会话；120条会话模拟数据只在浏览器响应中注入，没有新增120个数据库会话。1440×1000及1280×720下验证侧栏滚动、标题和输入框位置及页面不溢出。截图在screenshots目录。
