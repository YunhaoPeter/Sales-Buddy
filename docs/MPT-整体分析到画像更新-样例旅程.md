# MPT：整体分析到画像更新的连续样例

日期：2026-11-01。范围为Pencil原型与规划，本轮不开发系统。此文覆盖原规划中P10.95—112的旧页面索引、资源样例和分散确认流程。

## 1. 页面整理

18页收敛为10页，保留原编号以免影响其他设计引用。画布按主旅程先后排列，辅助状态置于后方。

主旅程：

1. **P10.95 整体分析报告**：阶段判断、项目现状、缺口、行动和内部资源。
2. **P10.96 行动落地**：一键添加待办成功回执及编辑入口。
3. **P10.98 资源联系**：从知识库匹配员工、工号、渠道与准备材料。
4. **P10.100 COME3.0**：周予安的会话与沟通草稿示例。
5. **P10.106 画像更新建议**：集中展示阶段与重点事项修改，用户确认。
6. **P10.110 更新完成**：阶段卡、事项、描述及更新记录同步展示。

辅助状态：P10.105来源实体清单、107矩阵阶段选择、108阶段补充追问、111待办编辑。

删除P10.97、99、101、102、103、104、109、112；分别合并到统一画像确认、资源联系、单份COME示例和更新结果。跳转同步调整，旧PNG移除。P10.42、43、48、113及首次M/P/T评估三列保留。

## 2. 一个项目贯穿全程

Coventry储能项目，Northstar Energy，OP-001，40MW/80MWh。初始有效画像M1:P2 / T2，与CRM实体阶段独立。

用户打开项目会话，请求整体分析。Agent使用当前画像及方法论，关联客户、联系人、决策链、商机、商机进展、商务活动和会议记录。只使用该项目的实际关联信息，不混入同客户其他项目。

样例初始事实：已开展预算询价，并网申请受理但尚未见批复，土地控制已有记录，核心许可和融资路径待确认；项目经理支持，但采购决策权限及实际推动行为未验证。

## 3. 整体报告

正文围绕销售决策，按以下顺序呈现：

- 一句当前判断：保持M1:P2 / T2，优先补齐可行性与决策链。
- 现状：客户、商机与进展、联系人及决策链、最近商务活动。
- 关键缺口与风险：并网、许可、资金路径、采购用途和支持者行为。
- 优先行动：核对RTB条件、引荐采购决策人、准备融资初筛。
- 内部资源：金融、并网专家、经济性分析分别能解决什么问题。
- 必要追问：已获何种审批、尚缺什么、支持者做了什么。

侧栏保留当前画像、独立T阶段、重点事项和本轮数据来源。正文不堆砌全部证据。外部信息只有主体匹配且有效才引用，本轮未引用时明确标记；不能用新闻推定审批或融资已完成。

## 4. 待办一键创建

绿色“添加待办”表示明确创建；紫色问题按钮表示继续讨论，只将全文带入输入框，由用户自行发送。

报告生成本身不创建任务。用户点击某项行动后，创建对应待办并展示P10.96回执；可继续编辑。P10.96以“核对RTB条件”为例，其他行动复用组件但使用各自标题、描述、负责人、截止时间和项目引用，不能写死为第一项。

后续实现约束：

- 卡片应先展示可读的任务摘要；缺少必填项时补齐再创建。
- 使用action_id及请求幂等键去重，同一行动重复点击不重复创建。
- 以CRM返回task_id为成功依据；失败保留建议并允许重试，不显示假成功。
- 任务创建不等于任务完成，也不自动改变项目阶段。
- P10.111保留待办编辑/既有草稿路径；活动与进展等其他创建仍按草稿确认规则处理。

## 5. 资源追问与联系

用户问“资源具体怎么联系、需要带什么资料”，Agent查内部资源知识库，返回支持范围、适用条件、材料、员工引用与渠道。

样例人员均明确标为示例：周予安，MOCK-FIN-021，集团供应链金融；顾文博，MOCK-ENG-017，电网接入；陈嘉宁，MOCK-TECH-032，储能经济性分析。联系方式为COME3.0按工号对接，不编造真实电话邮箱。

金融初筛需开发商及股权背景、资金缺口、经济性测算和审批状态；并网支持需申请/批复及技术约束；经济性支持需收益模型及CAPEX/OPEX假设。

P10.100演示周予安会话。其他员工复用该组件，后续按employee_id切换，避免每位同事复制独立画板。打开会话不自动发送，不代表同事接单或资源落实。

## 6. 对话驱动画像更新

后续销售补充：土地文件齐备、并网批复和核心许可已取得、项目经理已引荐采购负责人并安排评审，投资商仍未落实。用户要求“基于刚刚的对话更新画像”。

Agent只抽取用户真实补充与可信关联记录，不把自己的推断、建议或系统提示词当作销售已确认事实。对照阶段定义生成提案：M1:P2→M2:P3，T2保持。

P10.106集中呈现：

- 阶段原值、建议值、未变化维度及理由。
- 并网、许可、教练行为及资金落实的原标签、新标签和新描述。
- 文件原件待归档核验，销售申报与管理核验分别记录。
- 资金状态“已确认”表示明确尚未落实，不表示融资完成；因此不直接升级M3/M4。
- 确认更新、修改/补充、暂不更新三个出口。

受影响阶段的必需问题未问完或仍未知时，进入P10.108补充追问，明确后才进入统一确认。已知且有效的信息不机械重问。只修改事项且不足以支持升级时，阶段保持原值。

确认前正式画像和右侧卡片保持旧值。用户确认后，阶段与重点事项状态、描述共同保存，P10.110同步刷新；记录修改前后值、事实来源、确认人、时间和画像版本。后续需要版本冲突检查及一致性提交，防止旧会话覆盖新画像或部分保存却显示全部成功。

## 7. 既有入口与验证

P10.42更新阶段→P10.113；P10.43修改阶段→P10.107。两个弹窗的描述卡保持一致。保存选择只保存候选，再进入108追问、106确认、110更新。

本轮已检查主页面预览和指向删除页面的路由。原型回执、CRM写入和COME3.0均为设计状态，没有开发真实接口或发送消息。正式产品须让历史、对话与侧栏独立滚动，不能由长报告挤走输入框。
