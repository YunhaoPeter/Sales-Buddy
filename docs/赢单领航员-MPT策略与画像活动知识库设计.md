# 赢单领航员：MPT策略、画像活动与资源知识库

版本1.0，2026-11-01。本文是知识沉淀与编制规格，并给出可落地的核心内容。原始依据为“销售策略”目录的4页PPT与00—15工作簿；现有A/B/C专题库作为补充。企业实际能力、国家审批条件、资源联系人和待补规则须由对应负责人审核，不能把本文当作企业已授权政策。

## 1. 知识不是新闻列表

知识主体为可执行的销售活动：在什么条件下，问谁什么问题，执行什么动作，拿到何种结果，如何判断完成，未完成会带来什么风险，需要什么资源。外部新闻仅用于核真和触发复核，不替代活动方法论。

建议后续版本化目录如下；本次不更改在线索引：

```text
knowledge/navigator/
  catalog.json
  definitions/             # M、P、T与状态、主体、范围
  direction/              # 定方向：M/P/T问题包、36格、里程碑
    M/M0.md ... M5.md
    P/P0.md ... P5.md
    T/T0.md ... T5.md
    matrix/M0-P0.md ... M5-P5.md
  risks/                  # 识风险：条件、冲突、失效、动作
  resources/              # 递资源：能力与申请方法，不含私有目录
  activities/             # 阶段关键活动、完成判定与画像字段
  rules/                  # 转售、决策主体、重招、待补规则
  regions/                # 欧洲、北美、中东、亚太差异覆盖层
  scenarios/              # 脱敏训练与评估案例
  templates/              # 首访、核对、金融初筛、协同摘要
```

实际员工目录、内部关系和客户文件放入受控数据源。知识MD只引用目录ID和权限级别，不把私有手机号、客户文件或凭证提交到Git。

## 2. 一个知识条目的统一规格

每条具有：`id、version、pillar、title、M/P/T范围、采购主体模式、区域、项目类型、适用/排除条件、原资料定位、负责人、审核状态、有效日期`。

正文固定包含：

1. 本环节要解决的业务问题与进入前提。
2. 必问问题、条件触发问题、已知信息如何复用。
3. 事实与证据：用户口述、CRM记录、文件、外部信息分别如何使用。
4. 活动：责任角色、动作、产出、关闭标准、依赖及下一节点。
5. 画像字段：会影响哪些事项、阶段或风险，何时只生成候选。
6. 定方向：当前目标、下一里程碑与投入方式。
7. 识风险：触发信号、影响、验证动作与退出/控投条件。
8. 递资源：所需能力、适配前提、材料、目录引用、联系渠道。
9. 正例、反例及常见误判；来源/规则待补时如何回答。

知识发布状态建议为draft、business_review、approved、retired。模型默认调用approved规则；试验条目明确标注，不与正式规则混用。规则升级保留旧版供历史画像解释。

## 3. 三类知识体系与现有库衔接

### 定方向

- 项目核真与时间差：主体/SPV、别名、原始公告与最新动作。
- 项目落地：土地、并网、许可、收入、成本、融资、风险分配、NTP。
- 订单位置：首访、决策链、教练验证、优选/中标的书面和条件性区别。
- 采购窗口：预算询价、正式RFx、评标、定标及剩余范围。
- 投入策略：M×P格子、项目价值、可用窗口与支持成本。
- 下一步计划：找谁、问什么、交付什么、何时复核、达成什么条件。

### 识风险

- 项目真实性、主体/范围不一致、旧信息时间差。
- 土地权利范围不足、并网附加条件、核心许可未关闭。
- 收入假设、成本不可靠、融资路径或设备认可未核实。
- 单线关系、权限未知、教练行为失效、关键人离职。
- 口头优选、条件订单、转售不承继、投资换订单未经授权。
- EPC/业主/投资方权限变化、预算RFQ被当正式采购、重招或替换。
- NTP、合同生效、付款、交付、验收与回款依赖未关闭。
- 信息未知、证据冲突、过期或来源无权访问。

### 递资源

- C01信息资料和模板；C02客户/供应商/EPC/投资人关系入口。
- C03技术、并网、经济性与Bankability支持；C04接待和专业会晤。
- C05金融、信用、保险与投资协调；C06政府/公共机构正式办理与澄清。
- C07交付、调试、当地服务、验收与回款支持；C08高层与跨业务协调。

沿用现有`knowledge/strategic/定方向、识风险、递资源`专题ID，不复制一套同名内容。新增M/P/T适用标签、规则引用和活动ID；现有S阶段只作为独立筛选条件，不能决定MPT。

## 4. M阶段：关键活动与画像事项

### M0 规划

定义：有开发意图或规划，土地、并网、许可尚不明确。不能仅凭早期公告认定当前仍是M0。

- 问：项目主体是谁？区域/规模和应用是什么？团队有何实际动作？下一步准备推进什么、由谁负责？原始信息何时发布？
- 活动M0-01核真：销售结合CRM与公开信息确认主体、别名、SPV和时间线，产出项目身份卡。
- 活动M0-02路径讨论：与开发方梳理场址、接入和开发路径，产出下一实际动作及联系人。
- 活动M0-03首次接触：结合P位置形成联系路径、邮件或会面准备，产出客户愿意确认的问题。
- 画像：开发意图、主体、地区/规模、团队、最新动作、下一里程碑；未知保留未知。
- 演进：出现真实土地控制、并网或许可启动等开发动作时，核对后建议M1；规模大不构成升级依据。
- 风险：旧公告、同名项目、概念性规模、无后续动作。
- 资源：市场/产品信息、公开联系渠道、早期技术沟通；有明确问题后才申请重资源。

### M1 开发推进

定义：土地、并网、规划/许可已有启动，核心开发障碍尚未关闭。

- 问：土地控制取得什么？并网处于申请、受理、研究还是批复？哪些核心许可已取得、附什么条件？当前最大障碍和负责人是谁？
- 活动M1-01开发状态拆解：与客户逐项记录“已做、正在做、剩余条件、下一节点”，产出开发条件清单。
- 活动M1-02适用清单核对：由当地开发/工程角色确认本项目核心RTB事项，产出适用/不适用及理由。
- 活动M1-03技术经济支持：说明设备范围对可研、接入和收益的影响，记录预算RFQ用途，控制免费方案投入。
- 画像：土地、并网、许可分别保存业务状态、证据、有效期、责任人和节点，不能只存一个“审批已确认”。
- 演进：重大开发障碍基本关闭、具备可建设基础，经适用清单核对后建议M2。
- 风险：受理当批准、文件取得但条件未关闭、场址和线路范围不一致、关键节点无责任人。
- 资源：并网/场址专家、开发路径咨询、经济性初算及必要当地专业支持。

### M2 核心RTB

定义：重大开发障碍基本关闭，具备可建设基础；不代表融资关闭或立即开工。

- 问：核心RTB文件和剩余条件是什么？自持还是转售？未来业主/投资人是谁？选型是否将被新主体认可？资金和收入路径还有什么缺口？
- 活动M2-01证据与残余条件核对：核查适用核心事项及边界，产出RTB状态和残余条件清单。
- 活动M2-02交易与承继核对：识别自持/转售、未来主体和重采权，产出P归属复核事项。
- 活动M2-03投资级准备：协同客户明确收益、成本、融资、合同和采购路径，产出M3准备清单。
- 画像：核心RTB事实、转售安排、未来业主、设备认可、资金路径、合同承继。
- 演进：已有围绕可融资收入、预算、合同、采购和风险分配的实质推进，核对后可建议M3；不是必须先融资到账。
- 风险：RTB等于融资完成、只锁原开发商、忽略未来业主/重招权。
- 资源：经济性、融资初筛、投资/交易协调、合同及采购模式评审。

### M3 投资级RTB推进

定义：围绕可融资收入、可靠预算、合同、采购和风险分配推进。

- 问：融资卡点具体在哪个条件？收入模型及承购安排是什么？CAPEX/OPEX可信度如何？设备Bankability要求有哪些？谁采购、谁评标、谁签约？
- 活动M3-01融资条件拆解：客户财务与内部专业窗口梳理资金用途、缺口、准备材料、限制和时间，产出初筛需求单。
- 活动M3-02经济性验证：核对收入、成本、运行假设和敏感性，产出待核假设清单，不由销售承诺收益。
- 活动M3-03技术商务关闭：与采购主体核对RFx、偏差、竞争、EPC及投资方认可，产出关闭计划。
- 画像：融资进度/卡点、收入结构、预算、EPC、设备认可、风险分配、竞争和偏差。
- 演进：进入接近NTP、合同生效、采购和现场准备闭环的状态时核对M4条件。
- 风险：只问“有无融资”、口头投资意向当资金落实、优选当无替换风险。
- 资源：供应链金融/信用、投资人关系维护人、经济性与Bankability、技术商务专业团队。

### M4 开工准备

定义：接近NTP和开工，融资、合同、采购、交付与现场准备需闭环。

- 问：NTP哪些先决条件未关闭？合同是否生效？付款/担保条件是什么？谁发出开工指令？交付窗口、现场接口和剩余采购范围是什么？
- 活动M4-01CP/NTP核对：项目、商务和客户确认前置事项及责任人，产出按时间排序的关闭计划。
- 活动M4-02采购与替换复核：确认业主/EPC审批、定标、生效和替换条件，产出当前订单位置说明。
- 活动M4-03交付可行性：内部交付/供应链确认经授权的排期和接口，产出可执行交接清单。
- 画像：NTP、合同生效、付款/担保、采购审批、现场准备、交付依赖。
- 演进：有实际开工事实后建议M5，不能仅凭开工计划或采购定标认定开工。
- 风险：临近开工等于中标、忽略EPC/投资方审批、未经授权排产。
- 资源：合同、信用/担保、交付、供应链、现场接口负责人。

### M5 开工建设

定义：已实际开工，关注履约、变更、剩余范围、验收和回款。

- 问：我方是否已有合同？设备范围还有什么未采购？施工/交付进度如何？变更、测试、验收和下一付款条件是什么？
- 活动M5-01范围核对：区分已履约主订单和真实剩余采购，产出范围边界及新机会清单。
- 活动M5-02履约协同：记录交付、现场、性能或质保卡点，产出承接人和闭环节点。
- 活动M5-03验收回款：核对测试依据、签署角色、遗留项、付款触发与单据，产出闭环计划。
- 画像：实际开工日期、合同范围、交付/验收状态、遗留问题、回款、增容/二期。
- 演进：M5不再机械升为M6；以履约和剩余范围的业务里程碑推进。
- 风险：已建设仍盲追主设备订单、把增容或二期当作原订单、验收与收款混同。
- 资源：交付、质量、调试、当地服务、财务与回款协调。

## 5. P阶段：关键活动与画像事项

P必须绑定“当前决策主体+采购范围”。母公司关系、头衔、拜访次数和态度友好不能自动提高P。

### P0 无有效订单位置

- 目标：核真项目和最新M，找到可验证的首轮入口；CRM已是商机也允许P0。
- 问：旧信息日期？项目是否同一SPV/场址？是否已有人回复？联系人来源与业务权限是什么？
- 活动：Cross-check开发动作→公司/公开人员研究→合法公开联系路径→有针对性的首轮邮件准备。
- 产出/画像：原始与最新时间线、建议M及缺口、公开联系来源、下一联系目标。
- 判定：尚无有效接触不等于项目差；有效回复和持续接触证据可支持进入P1讨论。
- 风险/资源：不编造邮箱或私人关系；用C01信息、C02授权关系入口，不直接索取别人私有人脉。

### P1 接触与首访

- 目标：建立联系、必要NDA、首次沟通，识别当前真实M和初步决策链。
- 问：谁回复、什么角色？首访是否发生？谁影响技术/评标/定标？下一次能见谁？
- 活动：邮件与回复→NDA/资料范围→预约及按M准备问题→首访纪要→后续拜访。
- 产出/画像：联系人与职务、原话、角色假设、M事实、NDA状态和下一动作。
- 判定：关键决策角色的拜访已发生，支持或至少不反对我方参与，有持续渠道时可建议P2；不要求摸清所有角色才记录已知事实。
- 风险/资源：见到CEO不等于拿到订单；接待、售前或高层支持须有明确目标。

### P2 决策链支持

- 目标：覆盖关键链条，验证权限与态度，为有价值项目发展1—2名教练。
- 问：他能推荐、评分、批准还是否决？支持的是参与、方案还是最终选用？能否提供信息、提醒或引荐？
- 活动：角色权限核对→态度与保留条件记录→选择教练候选→低风险请求→跟踪实际结果。
- 产出/画像：角色、权限依据、支持原话、信息触达、教练候选与承诺/行为分离。
- 判定：至少一次可验证的有效信息、提醒、引荐或协调行为，且角色有效，才支持P3建议。
- 风险/资源：不反对不等于积极支持，饭局不等于教练；按项目价值选择投入，调用关系维护人与技术/会晤支持。

### P3 教练实际行为

- 目标：维护已验证教练、交叉核实采购与竞争信息，提前发现变化。
- 问：具体做过什么、何时、结果如何验证？信息来源仍有效吗？换岗/离职或主体变化了吗？
- 活动：记录行为证据→验证信息质量→维护关键关系→覆盖第二条线→推进下一书面里程碑。
- 产出/画像：行为、日期、渠道、结果、持续有效性、采购/竞争信息和下一请求。
- 判定：P4需结合M阶段判断早期开发绑定或正式优选，并具备相应书面及审批依据；教练不能代替定标。
- 风险/资源：长期失联仍标教练、只听单一内部信息；按需协调管理与专业资源，不宣称联系人能左右一切。

### P4 优选

- 目标：核优选类型、约束范围、主体和条件，降低替换/重采风险。
- 问：书面形式是什么？早期投资/开发绑定还是正式评选？谁批准？未来业主/EPC认可吗？有无重采权和未决条件？
- 活动：书面依据评审→生效/退出/承继核对→竞争与替换复核→关闭技术商务差异。
- 产出/画像：优选类型、范围、签署主体、约束和条件、审批、替换风险。
- 判定：P5需有适用的中标/订单依据及条件；M0—M2早期状态不等于无条件可执行订单。
- 风险/资源：M1×P4 SED规则待补，不能由模型自行套通用定义；需要合同、投资和采购专业评审。

### P5 中标

- 目标：区分条件中标、待生效与可履约状态，推进合同/CP及交付准备。
- 问：中标谁确认、范围是什么？合同是否生效？投资/融资/NTP条件是否满足？排产和交付由谁批准？
- 活动：中标依据核对→合同和先决条件关闭→授权交接→履约变更与回款跟踪。
- 产出/画像：书面结果、供货范围、合同状态、CP、剩余风险、交付/付款节点。
- 判定：P5不是所有条件完成的同义词，不自动改CRM为赢单或允许排产。
- 风险/资源：M1×P5规则待补；M0条件中标需核开发协议，M2需核转售承继，M3—M5需核合同/CP/履约。调用合同、财务、交付归口。

## 6. T阶段：独立采购任务与画像事项

### T0 未启动

- 问：有无有效设备采购活动？仅是规划、采购预告还是已经发出RFx？谁负责、预计窗口何时？
- 活动：记录未启动/预告及用途，准备设备价值和首轮交流；不凭M阶段推定采购已开始。
- 画像：主体、范围、计划窗口及信息日期；计划与已发生事件分开。
- 演进：真实RFI、RFQ或直接正式RFP可进入对应阶段，允许跳步。
- 风险/资源：采购预告当已启动；信息和技术交流资源即可，不默认投标重投入。

### T1 RFI 信息征询

- 问：谁发出、问什么、为了何种研究/筛选、截止日期及后续流程是什么？
- 活动：整理资格、技术资料与需求澄清，按适用版本回答，记录未满足资料。
- 画像：RFI文件/消息、目的、时间、主体、提交范围及后续窗口。
- 演进：实际RFQ/RFP或停止；提交RFI不自动提高P。
- 风险/资源：信息征询不等于近期采购；调用产品/资质资料维护人。

### T2 RFQ 询价

- 问：预算测算还是正式报价？供货边界、价格口径、有效期、时间及决策主体是什么？是否受PPA或投资决策影响？
- 活动：澄清范围、形成经授权报价/测算、记录条件和使用目的，计划下一采购核实。
- 画像：RFQ事件、用途、范围、报价条件、轮次与后续动作。
- 演进：设备正式RFP、评标等实际事件后才调整；预算RFQ可长期停留T2。
- 风险/资源：把报价当招标，把PPA竞标当设备T3；调用技术经济、报价和必要财务支持。

### T3 RFP 正式招标

- 问：正式文件、范围、资格、评分、竞争、截止日是什么？谁招标、评标、定标、签约？
- 活动：投标立项与投入判断→需求/技术商务偏差→决策链与竞争→按授权提交。
- 画像：RFP版本、招标主体、标准、资格、截止、偏差及交付文件。
- 演进：有实际评标/澄清事件进入T4，不能仅因提交文件就认定优选或中标。
- 风险/资源：不合格投标、时间不足、EPC/业主权责不明；投标、技术、商务、法务归口。

### T4 评标与澄清

- 问：评标到哪一步？哪些偏差未关闭？竞争者和替换条件是什么？有无重新询价/招标？
- 活动：澄清任务拆分→角色覆盖→偏差与条件交换→跟踪正式结果。
- 画像：澄清清单、评标事件、竞争信息来源、剩余问题、下一决定日期。
- 演进：正式定标进入T5；回到T2/T3或重招需记录原因和新轮次。
- 风险/资源：教练口述当正式结果、竞争信息未经核实；技术、合同、管理授权资源。

### T5 定标

- 问：正式结果和选定主体是谁？我方中标还是他人？范围、有效期和先决条件是什么？
- 活动：核定标依据→对照P/合同状态→关闭生效条件→组织交接或复盘剩余机会。
- 画像：定标日期/依据、结果、范围、条件及后续履约安排。
- 演进：T5不自动等于P5；我方可能未中标。后续采购以新范围或新轮次记录。
- 风险/资源：定标等于合同生效、追加范围自动继承；合同/信用/交付或复盘支持。

采购状态与T分开：暂停保留当前T并标原因；回退保留原事件；重招建立轮次；收入/PPA事件独立保存。

## 7. M×P 36格策略索引

每个格子均组合“核心动作+该M的落地缺口+该P的位置打法+实际T采购任务”。以下保留原PPT/工作簿语义，不用固定成交率替代策略。

### P0：无我方位置

- M0:P0 线索池：核最新动作，先验证主体与时间，找合规联系入口。
- M1:P0 线索核真：结合开发动作建议M，销售确认，联系开发角色了解障碍。
- M2:P0 好项目无我位：找真实入口、未来业主和转售路径，评估是否值得进入。
- M3:P0 采购可见无我位：看实际采购窗口、决策主体及差异化价值后决定投入。
- M4:P0 高危晚入：原则上不重投，先核真实剩余范围与进入可能。
- M5:P0 后续机会池：只找增容、运维、二期等独立范围，不虚构原主订单窗口。

### P1：接触与首访

- M0:P1 首轮联系：邮件、回复、NDA、首访，核意图与下一真实动作。
- M1:P1 首访核真：土地/并网/许可分别问进度，识别初步决策链。
- M2:P1 首访核RTB：核核心条件、转售安排、采购与未来业主。
- M3:P1 首访双问题包：融资具体卡点与采购全貌并行。
- M4:P1 晚期进入：先核NTP、采购窗口和可突破范围，限制投入。
- M5:P1 后续跟踪：核剩余采购、变更与增容机会。

### P2：决策链支持

- M0:P2 高潜选择性拜访：确认关键角色支持/不反对，按项目价值选择投入。
- M1:P2 决策链拜访：核土地/并网事实与角色权限，设计教练验证动作。
- M2:P2 关键链支持：结合项目价值决定教练投入，核未来业主及设备认可。
- M3:P2 采购链支持：覆盖业主、EPC和投资方，避免只跟一条线。
- M4:P2 晚期突破：严格控投，先核真实入口、审批及替换条件。
- M5:P2 后续机会：将变更、补供、增容分别识别并关联对应决策人。

### P3：教练

- M0:P3 信息教练：验证规划、团队、下一动作的信息质量。
- M1:P3 开发教练：通过信息、提醒、引荐验证行为，推动开发卡点核实。
- M2:P3 双线培育：核心RTB与教练行为并行，核投资/转售可能导致的主体变化。
- M3:P3 采购教练：获得可核实的融资、评标、竞争信息，推进偏差关闭。
- M4:P3 窗口教练：核审批、替换和NTP风险，不把教练当定标保证。
- M5:P3 履约/变更信息：支持后续范围，不追已建主订单。

### P4：优选

- M0:P4 早期优选/意向：低投入卡位，核书面约束与开发条件。
- M1:P4 SED规则待补：记录事实、文件和人工申报，不自动判断优选等级或升级。
- M2:P4 开发绑定优选：核新业主认可、重采权和设备/合同承继。
- M3:P4 正式优选：持续评估锁定程度，关闭技术商务、融资与审批条件。
- M4:P4 防替换/审批：核EPC、投资方和合同生效条件。
- M5:P4 异常复核：核剩余范围和状态是否仍适用，避免历史优选误读。

### P5：中标

- M0:P5 条件中标/意向：核开发协议及条件，不直接排产。
- M1:P5 SED规则待补：保留事实，不自动升级或形成履约承诺。
- M2:P5 早期条件订单：核投资绑定、转售承继和未来采购主体认可。
- M3:P5 中标待生效：关闭融资、合同及CP，保持条件清单。
- M4:P5 合同/交付准备：由人确认排产与交付条件、授权和窗口。
- M5:P5 履约/变更：关注验收、回款及剩余范围。

色块仅表达观察、培育、重点、冲刺/履约、风险控投、高危复核六种投入/风险语义。具体逐格色值以原PPT与P10.43为准，不由模型自由着色。推进方向可针对M或P单独变化，T轨迹独立。

## 8. 画像关键活动卡：字段与判断

每个M/P/T阶段的问题与活动都映射到`checkpoint_definition_id`，避免将回答拆成无限新增标题。

活动实例字段至少包括：

- 事项名称、适用阶段/主体/采购轮次、目标和适用理由。
- 本阶段已经做了什么、当前业务状态、未关闭条件与下一动作。
- 是否明确、谁确认、原话/记录引用、时间、有效期。
- 责任角色/具名责任人、目标节点及是否客户已承诺。
- 适用/不涉及/未知；不涉及原因和触发复核条件。
- 关联风险、资源、待办、历史变更与画像版本。

界面三种标签：

- **已确认**：信息被用户确认；描述仍可为“并网已受理、未批准”。
- **未明确**：信息不足或冲突待核，不能直接判为业务失败。
- **不涉及**：适用性已确认不适用，需保留原因；不是为了跳过问题随便勾选。

业务事项完成另看`businessStatus + closingConditions`。不得用“已确认事项占比达到80%”自动判M2或预测成交率。阶段推进取决于具体必需条件与例外，不取决于勾选数量。

## 9. 资源清单设计

### 资源目录字段

`resource_id、category、capability、regions、M/P/T适用范围、项目类型、前提、排除条件、材料、产出、归口部门、employee_refs、联系渠道、申请方式、费用/授权要求、可用性、最近核实时间、维护人、版本、访问级别`。

人员引用包括`employee_id、姓名、工号、岗位、部门、地区、COME身份映射、有效状态`。联系电话/邮箱只有真实目录提供且当前用户有权查看时展示。

### 首批资源条目

- R01 产品/公司标准材料：产品知识维护人；用于首访、RFI、方案解释；产出适用版本资料。
- R02 开发路径与当地事项：地区开发/专业方；用于M0—M2；需项目位置、主体、开发状态。
- R03 土地/场址与工程接口：工程/当地专业方；需场址边界、线路、施工条件；产出问题清单。
- R04 并网技术支持：电网接入专家；需申请/受理/批复和技术参数；产出接入约束及待澄清事项。
- R05 储能经济性分析：经济性团队；需收入模型、运行假设及CAPEX/OPEX；产出假设与敏感性分析，不保证收益。
- R06 Bankability技术包：产品/质量/认证/售前；需融资方资料要求与产品范围；产出适用文件及未满足项。
- R07 金融初筛/供应链金融：集团财务或真实金融归口；先识别资金用途、主体、缺口和前提；产出可适配路径或不适用意见，不保证额度/审批。
- R08 投资人或合作入口：真实关系维护人；需明确需求、已核实关系和披露授权；产出可申请引荐，不承诺投资。
- R09 投标与技术商务：投标/售前/商务；需RFx、标准、范围和截止；产出投标与偏差关闭计划。
- R10 合同、信用与担保：法务/信用/财务；需协议、CP、付款、担保；产出专业意见与授权流程。
- R11 接待/高层会晤：接待与管理归口；需角色、目的、议题和期待决定；产出专业议程与行动闭环，不以接待本身提高P。
- R12 政府/公共机构正式入口：当地专业或公共事务归口；需主管事项和申请主体；产出公开办理/澄清路径，不保证审批。
- R13 交付、调试与本地服务：项目/服务；需合同范围、地点、窗口、现场和验收要求；产出可交付性/服务边界。
- R14 回款与争议协调：财务/项目/商务；需付款条件、单据、验收和争议；产出下一付款关闭计划。

### 原型示例人员

- 周予安：MOCK-FIN-021，集团供应链金融，关联R07。
- 顾文博：MOCK-ENG-017，电网接入专家，关联R04。
- 陈嘉宁：MOCK-TECH-032，储能经济性分析，关联R05。
- 林知远：MOCK-INV-008，战略投资/投资者关系，关联R08；无需为其复制独立COME页面。

上述姓名/工号仅为原型示例。其余资源保持“归口待提供”，不要用虚构员工补满清单。

### 匹配顺序

先判断用户问题和阶段障碍→能力适用性→项目地区/类型→前提与材料→权限→有效归口及可用性→输出匹配理由。先做硬过滤，再排序，不只按词相似度推荐。

“无匹配”“前提不足”“归口未核实”“目录无权访问”需要区分；不相关资源不凑数。关系共现、参加同一会议或共同供应商不等于有可用引荐链。

## 10. 地区和业务模式覆盖

欧洲、北美、中东、亚太均作为覆盖层，主M/P/T定义不按国家复制四套。每条地区知识记录国家/市场、适用技术、事项、有效日期、专业审核人及来源。

- 欧洲：重点补各国站点/许可/接入、收入组合、投资人/EPC及服务要求的差异。
- 北美：重点补管辖、电网/市场、项目主体、接入队列与设备采购范围的差异。
- 中东：重点补业主/EPC/投资方模式、正式采购、接待与本地服务支持边界。
- 亚太：重点补不同国家收入/用能场景、接入/许可、当地伙伴与交付条件。

以上为知识采集方向，不是对任何国家审批或市场机制的具体法律结论。未审核的地区细节不能用于自动定级。

项目模式至少区分大型独立储能、可再生能源配储、工商业储能、渠道/集成商项目。模式影响适用事项和资源，不改变“P绑定主体、T只认设备事件”的原则。

## 11. 训练案例与发布验收

首批至少覆盖以下代表案例：

1. 去年规划M0，最新有并网申请：建议复核M1，不覆盖原有效值。
2. 采购经理说方案好：记态度，不直接P3。
3. 提供评标时间并完成引荐：可形成P3建议，保留角色与结果依据。
4. M2转售，原开发商P4：新业主不自动继承，触发主体复核。
5. M3尚缺投资商：问融资卡点和其他投资级条件，不因未融资直接退M2。
6. PPA竞标期间预算RFQ：收入事件与设备T2分别保存。
7. EPC代采、业主否决：同时覆盖两者权力，不只看联系人头衔。
8. T4重新询价或重招：保留原轮次事件，不覆盖轨迹。
9. M1:P4/P5：明确规则待补，保留事实与人工申报。
10. 建设中发现增容需求：作为剩余/新增范围，不追已建主订单。
11. 并网受理状态被用户确认：信息已确认但未获批，不自动M2。
12. 用户说“帮我问有没有融资”：是请求，不写成融资事实。
13. 同客户两个项目分别审批：严格项目归属，不混写画像。
14. 资源目录有金融能力但项目条件不足：输出初筛前提，不承诺融资。
15. 用户取消画像提案：观察可保留，正式阶段不变。

每个案例保存输入、已有事实、期望问题、允许建议、禁止结论、适用知识ID及评估规则。业务负责人审核后才能作为正式判断基线；模型输出与基线不一致时可追溯到规则版本和事实缺口。
